# llmcli 会话落盘语义修订 PRD

> 版本：v0.1（`turn`/`ts` 归属 + 逐 turn 落盘） | 日期：2026-09-29 | 状态：草稿（待评审） | 作者：（待填） | 评审人：yuekcc

摘要：为使用 `--session-id` 续话与复盘的使用者，解决"会话文件既不是完整的、也不是忠实的"的问题，达成"每个 turn 完整结束即落盘、每条记录自带所属轮次与发生时刻"的目标。

## 背景与问题

**背景**：001 PRD 的 T5.2/T5.3 已交付 `--session-id` 本地落盘续话，实现为"一次 Trace 在**成功后**一次性追加全部消息"。一次真实运行（`run.sh`，模型 hy3，会话文件 `ses_1790684668.jsonl`）暴露三处偏差：

| # | 实测现象 | 影响 |
|---|----------|------|
| 1 | 4 条记录的 `turn` 全写成最终轮（都是 `2`），而同一次运行的 stderr 明明是 `[turn 1] … [turn 2] …` | 文件读不出 Trace 的轮次结构，按轮复盘/回放失真 |
| 2 | 4 条记录的 `ts` 全等于落盘那一刻（`20:24:44`），而这次运行实际跨了约 16 秒（turn 1 3.4s + turn 2 12.1s） | 每条消息的发生时刻丢失，看不出哪一轮/哪个工具慢 |
| 3 | 只有拿到最终答案才写一次：网络/协议错误（退出码 1）、`--max-turns` 止损或无最终答案（3）、Ctrl+C（130）都不写 | 长 Trace 中途失败即全丢，既无法续话也无法事后排查 |

**问题**（一句话）：会话文件对外承诺是"Trace 的完整记录"（001 假设 7「全量记录 user/assistant/tool」），但现状既**不完整**（失败即全丢），也**不忠实**（轮次与时刻被整批覆盖成落盘那一刻的值）。

## 目标

| 指标 | 基线 | 目标值 | 时间窗 | 数据来源 |
|------|------|--------|--------|----------|
| `turn` 归属 | 整批写成最终轮 | 每条记录的 `turn` 等于 stderr 的 `[turn N]`；两轮工具 Trace 依次为 `1,1,1,2,2,3` | 本次修订 | `c3c test` + `scripts/regress.py` |
| `ts` 归属 | 整批写成落盘时刻 | 每条记录是消息发生的时刻；跨秒 Trace 的首尾记录落在不同秒 | 同左 | 同上 |
| 中断/失败后的可续性 | 0（不落盘） | 报错、`--max-turns`、Ctrl+C 后已完成的 turn 100% 在文件里 | 同左 | `scripts/regress.py` S3 |
| 历史合法性不变量 | — | 文件里每个 assistant `tool_calls` 都能找到对应 `tool` 消息（0 例悬挂），`load` 无坏行告警 | 同左 | 回归断言 |

## 范围与约束

**包含**：`session::Record` 携带 `turn` 与 `ts`（都在消息产生时取值）；`session::append` 的原子单位由"一次 Trace"改为"一个完整 turn"；agent loop 在 turn 完成点落盘；`ts` 仍为秒级 RFC3339（本地时区）；docs 与 `--help` 同步。

**不包含**：`ts` 亚秒精度（`RFC3339ZMS`）；跨进程会话锁；会话文件清理/轮转；把系统提示词与 tools schema 也入库（仍每次运行重新注入，见 `docs/sessions-and-ci.md`）；恢复"只在成功时落盘"的开关。

**假设与已定决策**（2026-09-29 评审确认）：

1. `turn` 是**每次运行内**的请求轮号，与 stderr 的 `[turn N]` 一致；续话时新一轮从 1 重新计，不做跨运行累计编号。
2. `ts` 是**消息发生的时刻**：user = 本次运行开始，assistant = 响应到达，tool = 工具跑完；不再共用落盘时刻。
3. 落盘时机改为**每个 turn 完整结束后立刻追加**：整轮一次 write，绝不写半截 turn（assistant 的 `tool_calls` 必须与它的 `tool` 结果同批写入）。
4. user 输入属于 turn 1，随 turn 1 一起落盘；turn 1 未完成（首个请求就失败）则本次输入不落盘——不产生孤立的 user 消息。
5. 未给 `--session-id` 时全程不落盘（不创建文件）。

**修订 001 的条目**：

- T5.2 AC1「Given 首次运行 `id=s1`，**When 成功**，Then 新建会话文件并追加**本轮**全部消息」→ 改为「**When 每个 turn 完整结束**，Then 追加该 turn 的消息；Trace 失败/中断时，已完成的 turn 已在文件里」。
- 001 假设 7 的行格式（一行一条 JSON，含 `ts`/`turn`/`message`）不变，但 `ts`/`turn` 的语义以本 PRD 为准。
- 001 风险表「会话文件并发写 → 追加原子写」的粒度由"一次 Trace"降为"一个 turn"：仍然**每批一次 write、不产生行交错**，只是交错窗口变多。
- 001 未决的 S5 限制类机制（超时/输出截断/失败阈值）不受影响。

**依赖**：`std::time::datetime`（RFC3339 本地时区格式化）；`scripts/mock_llm.py` 需具备"同一 Trace 内连续调用同一命令"的场景（已新增 `two_bash_calls`），用于观测 Trace 中途的落盘状态。

**风险**：

| 风险 | 影响 | 缓解 |
|------|------|------|
| 失败/中断的 Trace 现在会留下部分历史 | 续话可能从"中途状态"继续；文件里出现不完整对话 | 只落**完整 turn**（末尾必然是 `tool` 或最终答案），`load` 必得合法前缀；docs 与 `--help` 明示落盘时机；要干净会话就删文件（001 已定：不提供清理功能） |
| 落盘次数从 1 次/Trace 变为 1 次/turn | 长 Trace 写放大（每轮几 KB） | 每批一次 write，与消息体同阶；文件增长风险 001 已记录 |
| 多进程同 id 并发 | 行交错窗口变多 | 仍按批单次 write，行级不交错；只可能出现"轮次混排"（001 已接受） |
| `ts` 仍为秒级 | 同一秒内产生的相邻消息 `ts` 相同 | 记录的是真实时刻；需要更细粒度时升级为 `RFC3339ZMS`（见开放问题） |

**非功能**：

- 可观测性：单次 `append` 失败仍只 warn 并继续，不中断本次运行（同 001）。
- 数据完整性：`Record` 由调用方在消息产生时构造，从类型上避免"整批共用一个值"的回归。
- 兼容性：文件仍是 JSONL、字段不变；旧文件（`turn` 全为最终轮、`ts` 为落盘时刻）仍可 `load` 续话。

**关键流程**：

**活动描述**：

- **A6 会话落盘与读回**（本 PRD 新增活动；修订 001 的 T5.2 会话落盘续话）
  - **T6.1 记录所属轮次**
    - As a 复盘问题的使用者, I want 每条记录带上它所属的 turn, so that 会话文件能还原 Trace 的轮次结构
      - AC: Given 两轮工具调用的 Trace, When 落盘, Then `turn` 依次为 `1,1,1,2,2,3`
      - AC: Given 单轮工具 Trace, When 落盘, Then `turn` 依次为 `1,1,1,2`，与 stderr 的 `[turn N]` 一致
      - AC: Given 续话的新一轮, When 落盘, Then 新记录从 `1` 重新计，且已有记录逐字段不变
      - 优先级/切片：Must / S6 ｜ 依赖：无
  - **T6.2 记录发生时刻**
    - As a 复盘问题的人, I want 每条记录是消息发生的时刻, so that 能看出每一轮与每个工具的耗时
      - AC: Given 工具耗时 2 秒的 Trace, When 落盘, Then 首尾记录的 `ts` 落在不同秒
      - AC: Given `append` 收到自带 `ts` 的记录, When 落盘, Then 原样写入，不被落盘时刻覆盖
      - 优先级/切片：Must / S6 ｜ 依赖：无
  - **T6.3 逐 turn 落盘**
    - As a 长时间跑 Trace 的人, I want 每个 turn 完成即落盘, so that 中断或报错不会丢掉已完成的轮次
      - AC: Given `--max-turns 2` 且模型持续要工具, When 进程以退出码 3 结束, Then 文件里有两个 turn 的 `user/assistant/tool` 记录
      - AC: Given 任一时刻检查文件, Then 末尾是完整 turn（不存在没有 `tool` 结果的 `tool_calls`）
      - AC: Given 已落盘的前缀, When 续话, Then 请求携带该前缀，且每个 `tool_calls` 都有对应 `tool` 消息、读回时无坏行告警
      - AC: Given turn 2 的工具去读会话文件自身, When 它执行, Then 已能读到 turn 1 的记录（证明写入发生在 Trace 结束前）
      - AC: Given 未给 `--session-id`, When 运行, Then 全程不创建文件
      - 优先级/切片：Must / S6 ｜ 依赖：T6.1、T6.2（同批写入）
  - **T6.4 读回合法前缀**
    - As a 续话的使用者, I want 中断后 load 到的历史是合法的, so that 续话请求不会被端点拒绝
      - AC: Given 只落了部分 turn 的文件, When `load`, Then 消息序列完整（每个 `tool_calls` 有对应 `tool`）且不产生坏行告警
      - 优先级/切片：Must / S6 ｜ 依赖：T6.3

| 问题 | 影响 | 状态 |
|------|------|------|
| `ts` 是否升级到毫秒（`RFC3339ZMS`） | 同一秒内的多条记录 `ts` 相同；改格式需同步 docs/`--help`/回归断言 | 待定 |
